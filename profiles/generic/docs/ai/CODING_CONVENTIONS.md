# اتفاقيات الكود

## عام
- اللغة في الكود: الإنجليزية.
- اللغة في التعليقات: [عربي / إنجليزي].
- الطول الأقصى للسطر: 100 حرف.
- التنسيق: [Prettier / ESLint / ...].

## التسمية
- المتغيرات والدوال: camelCase.
- الثوابت: UPPER_SNAKE_CASE.
- المكونات والكلاسات: PascalCase.
- الملفات: [kebab-case / camelCase / PascalCase].
- المجلدات: kebab-case.

## تنظيم الملفات
- كل ملف له مسؤولية واحدة.
- لا يزيد الملف عن [300] سطر دون سبب.
- الاستيراد مرتب: مكتبات → ملفات داخلية → أنواع.
- المسارات المطلقة أفضل من النسبية المتشعبة.

## الدوال
- كل دالة تفعل شيئًا واحدًا.
- أسماء واضحة تعبّر عن الفعل.
- تجنّب المعاملات أكثر من 3 إن أمكن.
- لا تُرجع قيمًا من نوع غامض.

## الأنواع (Types)
- استخدم TypeScript strict.
- لا تستخدم `any` إلا لضرورة موثقة.
- عرّف الأنواع في `types/` أو قرب الاستخدام.

## معالجة الأخطاء
- لا تُخفِ الأخطاء.
- استخدم try/catch عند التعامل مع I/O.
- رسائل الخطأ واضحة ومفيدة.
- لا تُرجع رسائل خطأ داخلية للمستخدم النهائي.

## السجلات (Logging)
- استخدم logger موحد.
- مستويات: debug, info, warn, error.
- لا تسجّل بيانات حساسة.

## الاختبارات
- كل دالة مهمة لها اختبار.
- أسماء الاختبارات: `should [behavior] when [condition]`.
- شغّل الاختبارات قبل التسليم.

## Git
- رسائل commit بصيغة: `type(scope): message`.
- الأنواع: feat, fix, refactor, docs, test, chore.
- فرع لكل مهمة: `feature/T-XXX-وصف`.

## الممنوعات
- لا كود ميت.
- لا تعليقات مضحكة أو غير مهنية.
- لا مكتبات جديدة بدون موافقة.
- لا `console.log` في كود الإنتاج.
